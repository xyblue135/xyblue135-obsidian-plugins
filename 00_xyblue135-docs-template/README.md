# xyblue135 · 元数据补全

> **开源插件**：xyblue135 维护的开放源代码插件，仓库公开、可自由查看与复用。
> **兼容原则**：插件 ID 保持 `00_xyblue135-docs-template`，升级包不携带 `data.json`，覆盖安装时保留用户本地配置与历史状态。

维护者：**xyblue135**

---

## 功能

用 Obsidian **原生的方式**新建 `.md` 就行，插件负责给它补齐 YAML frontmatter：

- 不做「新建模板笔记」入口——没有 ribbon 图标，也没有文件夹右键菜单项。新建笔记完全走 Obsidian 自带的 `Ctrl+N` / 右键「新建笔记」/ 双击空白处。
- **创建后自动审查**：白名单目录内的 `.md` 被创建后，延迟检查 frontmatter，**只追加模板里有、笔记里缺失的字段**；已有字段的值与顺序一律不动，正文也不动。
- 模板支持 `{{folder}}`、`{{filename}}`、`{{path}}`、`{{datetime}}`、`{{date}}`、`{{time}}`、`{{timestamp}}` 等变量。
- 设置页可直接编辑并保存默认 YAML 元数据模板。
- 不依赖 Templater。

## 审查模式

- **作用域白名单**：默认 `00_docs`，支持逗号分隔多个目录（如 `00_docs, 00_暂未分类`），自动包含子目录；留空表示整个仓库。
- **新建的空笔记立即补全**：Obsidian 新建笔记后会立刻在编辑器里打开它，此时缓冲区是空的——这属于「可以马上补」的状态，会在第一次延迟到点后直接补全，不需要切走再切回。
- **不会和打字抢跑**：笔记正在编辑器里打开、且你已经写了内容时，补全写进编辑器缓冲区（而不是直接写磁盘），并且在 frontmatter 补齐前会先顺延几轮，等你停下来再补，你正在输入的内容不会被覆盖。
- **frontmatter 未闭合会跳过**：只有开头 `---`、还没写闭合 `---` 的笔记会被判定为「写到一半」，本次跳过并提示，不会把整块模板硬塞到文件最前面。
- **完全没有 frontmatter** 的笔记，会把整块模板补在正文最前面。
- **手动命令**：
  - `审查并补全当前笔记的模板字段`（可绑定快捷键）
  - `审查并补全白名单内全部笔记`（批量修复历史笔记，执行前弹确认框）
- 补全延迟、开关、白名单均可在设置页调整。

> 批量补全前建议先 `git commit`，便于回滚。

## 版本变更

- **1.5.0**：移除「新建模板笔记」的两个入口（左侧 ribbon 图标、文件树文件夹右键菜单项）及其设置项；修复「新建的空笔记要切走再切回才补 frontmatter」的问题。
- **1.4.0**：新增审查模式（创建后自动补全缺失字段）。

## 安装

保持插件目录名 `00_xyblue135-docs-template`，复制到 Vault 的 `.obsidian/plugins/` 下后，在第三方插件中启用 **xyblue135 · 元数据补全**。

升级覆盖时保留当前插件目录中的 `data.json`，不要提交到公开仓库。
