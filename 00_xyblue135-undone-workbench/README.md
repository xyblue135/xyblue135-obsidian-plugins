# xyblue135 · 待完成工作台

筛选白名单目录里 `status: 🔴 undone` 的笔记，逐篇分析还差什么，引导你**一篇一篇**处理。

## 设计原则

- **不做一键批量完成**。status 始终由你自己在笔记里手动改动，本插件对 status 只读不写。
- 处理完一篇、把 status 改成 `🟢 done` 后，它会自动从清单里消失（监听 metadataCache，约 2 秒内刷新）。

## 清单分析（每篇待完成笔记）

| 检查项 | 判定 | 引导 |
| --- | --- | --- |
| AI 元数据 | `AI_tags` / `AI_summary_short` / `AI_technical_depth` / `AI_title` 缺失 | 「打开并生成 AI 元数据」联动 AI 元数据插件，为当前笔记生成全部字段 |
| 内容体量 | `token_count` 低于阈值（默认 300） | 提示「疑似占位笔记」，回笔记补正文 |
| 搁置时长 | `updated` 超过阈值（默认 90 天） | 提示先确认内容是否仍有效 |

## 动作

- **打开笔记继续写**：在新标签页打开。
- **打开并生成 AI 元数据**：先打开笔记，再执行「AI 元数据」插件的 `generate-summary-and-tags`（全部 10 个字段）。未安装该插件时按钮自动隐藏，并给出 Notice 提示。
- **在导航图中查看**：跳转「知识库导航」插件视图，看这篇笔记在整体结构里的位置。
- **下一篇 →**：按当前排序跳到下一篇待完成笔记，支持逐篇流水线处理。

## 排序

按最近更新（默认，先处理还热的）/ 按内容最少（速赢优先）/ 按路径。

## 设置

- 白名单目录（每行一个，默认 `00_docs`）
- 搁置阈值天数（默认 90）
- 占位笔记 token 阈值（默认 300）
